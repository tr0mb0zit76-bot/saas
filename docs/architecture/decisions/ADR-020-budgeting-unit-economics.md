# ADR-020: Бюджетирование — юнит-экономика найма, не полный УУ

**Status:** Accepted  
**Date:** 2026-11-10  
**Related:** ADR-003 (module packaging), ADR-006 (feature gating), ADR-002 / ADR-010 (tenant isolation)  
**Team input:** saas-architect · CFO brief (×2) · saas-qa · saas-privacy · saas-security (2026-11-10)  
**PO decisions:** 2026-11-10 (per_head + взносы в P0; УУ = только plan vs actual)

## Context

Модуль «Бюджетирование» (`feature:budgeting`, Enterprise) уже есть в SaaS: сценарий, OPEX-статьи (`fixed_monthly` / `percent_of_margin`), top-down / bottom-up, снимки плана, опциональная связь с `management_expense_categories`.

Пилот Orientum показал UX/семантические боли:

1. **`manager_count` масштабировал только маржу** (`margin_per_manager × N`). ФОТ («Оклады менеджеров») — lump `amount_monthly`. Решение «нанять ещё» завышало поток.
2. **Узкий каталог** (офис / бухгалтерия / ФОТ) → оптимистичный «ноль месяца» и дивиденды.
3. **Подписи «касса / безубыточность»** обещают cash; модель = маржа − OPEX без DSO/DPO, налогов, взносов.
4. **`ramp_months`** = `month <= N`; UI «первые N мес.» путает с окладом на весь горизонт.
5. Управленческий учёт + бюджетирование — **вне MVP 6 мес.** (ADR-003 / AGENTS); модуль = Enterprise-пилот.

Математика дублируется PHP (`BudgetPlannerService`) ↔ JS (`budgetPlanner.js`). Unit `tests/Unit/Budget*` не в CI job `tests/Feature/Saas/`. Изоляция `BelongsToTenant` есть; Feature-тестов cross-tenant IDOR / мутаций без feature почти нет.

CFO-вердикт по **удобству формирования бюджета** в текущем виде: **2/5** (хороший скелет найма; не бюджет компании). После P0 целевая оценка **~3.5–4/5** как «план безубыточности и пика финансирования».

## Decision

### 1. Продуктовая рамка

Модуль = **«план выхода в ноль / калькулятор найма»**, не полный УУ и не кассовый бюджет.

- Тариф: **только Enterprise** (`budgeting`).
- Дисклеймер обязателен; касса DSO/DPO — P2 на данных payment schedules.

### 2. Locked PO decisions (2026-11-10)

| # | Решение |
| --- | --- |
| 1 | **`manager_count` связан и с маржой, и с ФОТ:** `per_head = rate × N`. Не lump. |
| 2 | **Страховые взносы в P0** (процент к окладу / к per_head-базе), не откладывать в P1. |
| 3 | Бюджет = **планирование**. Связь с УУ **только** как «насколько соответствуем бюджету» (plan vs actual). **Нет** жёсткой привязки ввода статей к категориям УУ. |
| 4 | **Сразу семантика `per_head`**, не «только подписи» при сохранении старой формулы. |
| 5 | ADR Accepted с этими решениями. |

### 3. Семантика драйверов (P0)

| Концепт | Канон |
| --- | --- |
| Маржа компании | `margin_per_manager × manager_count` (bottom-up) / деление цели на N (top-down) |
| ФОТ менеджеров | **`per_head`**: ставка × `manager_count`. `fixed_monthly` остаётся явным режимом «на всех» для прочих статей |
| Взносы (P0) | Надбавка % к ФОТ per_head (или к выбранной базе оклада); role bucket, без ФИО. Параметр % с подсказкой МСП / общий режим |
| Именованные оклады / `user_id` на OPEX | **Запрещены**. Зарплаты по людям — `finance_salary` / УУ |
| `ramp_months` | «Действует N мес.» / «весь горизонт»; для оклада default = весь горизонт |
| Вехи | **Ноль месяца** (net ≥ 0), **окупаемость** (cumulative ≥ 0), **цель** (дивиденды/резерв). Не смешивать «безубыточность» |
| Cash honesty | Дисклеймер: без налогов, ОК, отсрочек. Метрика **пик финансирования** |
| Snapshot | Версия формулы до смены семантики |

### 4. Каталог OPEX и УУ (P1+)

P1 шаблон ICP (без обязательного УУ): бонус `% маржи`, ФОТ не-продаж, аренда, IT/место, маркетинг, страхование, банк/ВЭД, резерв, **налог с базой** (оборот / маржа / прибыль, без silent default). Перевозчик **не** в OPEX.

Опциональная привязка статьи → `management_expense_category_id` (tenant-scoped) — только чтобы plan vs actual сравнивался; ввод бюджета от УУ **не зависит**.

P2: сценарии «+N» с пересчётом ФОТ+взносов; soft plan vs actual; cash DSO/DPO; цель после налогов.

### 5. Privacy / RBAC

- Драйверы: роль × численность × ставка (+ взносы %), без ФИО.
- При `n = 1` не подавать «на человека» как персональный оклад.
- Не обходить `finance_salary` именованными суммами в props.

### 6. Тестовый gate

- Feature/Saas: gate на все `budgeting.*` мутации; cross-tenant 404 на OPEX; index без чужих данных.
- Unit: `per_head` × N (+ взносы); lump не зависит от N; `company_margin = mpm × n`; `ramp_months`; паритет PHP↔JS или удаление JS-копии.
- CI реально гоняет бюджетные тесты.

## Consequences

### Positive

- Найм: N двигает маржу и ФОТ+взносы вместе — доверие CFO.
- Честная рамка «план / пик финансирования», не «полный бюджет».
- Privacy: role buckets.
- УУ не блокирует планирование.

### Negative

- Миграция Orientum lump 450k → ставка × 3 (+ взносы) сдвигает вехи на экране.
- Без каталога/налогов/WC P0 всё ещё не «годовой бюджет» (CFO ~3.5–4/5).
- Support по % взносов (МСП vs общий).

### Mitigations

- Дисклеймер + пик финансирования в P0.
- Подсказка % взносов, не silent «правильно для всех».
- Налог / WC явно в P1/P2; онбординг: «не заменяет Excel по налогам и кассе».

## Alternatives considered

1. **Только подписи, формула lump** — отклонено PO (ответ 1 + 4).
2. **Взносы в P1** — отклонено PO (ответ 2).
3. **Жёсткая привязка статей к УУ** — отклонено PO (ответ 3).
4. **Именованные оклады** — отклонено privacy/RBAC.
5. **Полный УУ / касса в P0** — отклонено (вне MVP, объём).

## Open questions

Нет блокирующих для старта P0. Единственный продукт-чеклист перед кодом: явное «утверждаем P0?» на refined plan (взносы % UX: одно поле на статью ФОТ vs глобальный % сценария — на усмотрение реализации, default глобальный % к сумме per_head ФОТ менеджеров).
